rq · review queue · design spec v1 · Oct 2026

One review queue for GitHub and GitLab, run like an editor

rq lists every open PR you care about across both forges, sorted into sections. You move with vim keys, act with single keys or a : command line, and read state from aligned glyphs instead of badges and boxes. The loop it serves: triage what agents opened, review, arm auto-merge, walk away, come back to a clean list.

Mockups are rendered in the Unicode glyph tier at truecolor. Use the Tweaks panel to switch every screen to ASCII glyphs or 16 colors, or try another accent.

State glyph. One column summarises merge readiness: ✓ ready, ○ waiting (CI running or reviews short), ✗ failing, ≠ conflict, ◌ draft. Precedence runs draft → conflict → failing → waiting → ready.
Armed. ◆ in its own column, in accent, so a batch of armed rows reads as a stripe. Agents carry ◇ before their name; humans carry nothing.
Forge. A dim gh or gl tag. Numbers always use #; GitLab's !812 is shown as #812 and both spellings are accepted in commands.

PR detail and review

The top block is the merge verdict: one word (READY, WAITING or BLOCKED, the only filled label in the app) with a sentence saying what happens next, then the four facts behind it. Below, a scrolling overview on the left and the diff on the right. h/l move focus between panes; the focused pane's heading is accent. d zooms the diff to full width.

{{ s.t }}
READY (green): M merges after the one-key confirm. Sentence: "Nothing blocking. M merges with squash."
WAITING (yellow): only time or other people are needed. If armed, the sentence says when it will merge; if not, "A arms auto-merge."
BLOCKED (red): failing checks, conflicts, changes requested or draft. The sentence names the first blocker and the key that helps (d, o, :checkout).

Unicode is the default tier: every glyph is single-cell in Ghostty and WezTerm and needs no patched font. glyphs = "ascii" or "nerd" swaps characters only; widths and layout never change between tiers.

Spacing and alignment
  • Two-cell left gutter (cursor, mark), one-cell right margin. Content starts at column 2 on every row, including tabs.
  • Fixed-width columns, at least one space apart. Numbers right-aligned; text left-aligned; glyph columns one cell plus one space.
  • No boxes. One faint │ between side-by-side panes. Overlays and menus use the surface fill.
  • One blank row between groups, never two. Headings are lowercase dim words; only PR titles and section names use their own casing.
  • Durations are compact and right-aligned: 12m 3h 2d 1w.
  • Titles truncate at the end with …; repos shorten to the name after the slash before they disappear.
Status line
MODE section pos/count [marks] ····· ◆ n armed ✗ n failing sync|E error gh ✓ gl ✓
  • Modes: NORMAL, COMMAND, FILTER (accent) and CONFIRM (warn). The block is never red.
  • Left side is about where you are; right side is about the world: global armed and failing counts, sync age, per-forge health.
  • A background error replaces the sync segment in red and the forge's ✓ becomes ✗ until it recovers.
  • Below 100 columns the counts drop their words (◆7 ✗3).

One row per PR, one combined state glyph, everything else in aligned columns. Densest: 34 PRs on a 40-row screen. Reads best when sorting by recency across many repos.

Interaction spec

  • Sections are queries from the config file, written in one forge-neutral syntax and translated per forge. Counts update on every sync. Each section remembers its cursor, scroll and filter.
  • Cursor stability. Refresh keeps the cursor on the same PR by id. If that PR left the section, the cursor stays at the same index.
  • Readiness is ✓ only when required checks pass, required reviews are met, there are no conflicts, it is not a draft, and the branch is up to date where the repo requires it.
  • Confirmation is required for M, x, :merge and :close, and for any action on more than one PR. It is one key on the command line. Arm, disarm, approve and comment run immediately.
  • Armed lifecycle. armed → waiting (on CI, reviews, or a merge train) → merged, or → needs attention when a check fails, a conflict appears, changes are requested, or the forge disarms it. Transitions from waiting to merged or needs attention ring the terminal bell and send an OSC 9 notification (configurable).
  • Messages. Command results stay on the last row until the next key. Background errors stay on the status line until resolved. :messages keeps the last 200 of both.

Mouse (optional)

Click a row to select, double-click to open; click a tab to switch section; the wheel scrolls the pane under the pointer. Nothing is mouse-only.

Ghostty and WezTerm

Truecolor by default. Kitty keyboard protocol so Tab, ^i and S-Tab are distinct. Synchronized output (mode 2026) on every redraw to avoid flicker. PR numbers are OSC 8 hyperlinks, so cmd-click opens them. Match highlights use a styled underline where supported.
